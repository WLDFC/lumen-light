# LumenLight 云端部署说明（Windows Server VPS）

> 目标：把后端部署在公网 VPS 上，本地/任意设备用浏览器访问。
> 用途定位：API 生成 + 网页桥接（Comfy/放大/抠图等本机 GPU 功能不在此方案范围）。
> 本地项目源码零改动——云端方案全部在 `cloud/` 文件夹内。

## 架构

```
浏览器 → https://你的域名 (Caddy:443，自动HTTPS) ─┐
浏览器 → http://VPS公网IP:8081 (IP直连门) ─────────┤
                                                   ▼
                                    cloud/gateway.js (鉴权+出站地址改写)
                                                   ▼ 反代 HTTP+WS
                                    原始 server.js (:8080，原样不改)
```

- **两扇门同一把锁**：访问码（token）登录页 → HttpOnly cookie（30 天免登录），
  HTTP 与 WebSocket 统一拦截；登录失败同 IP 10 分钟 8 次即锁（防爆破）。
- **8080 绝不对公网开放**：公网上不存在绕过网关锁的后门。
- **9 处写死的 localhost:8080**（`js/api/LumenSocket.js` 的 WS 连接等）由网关
  出站改写成同源地址，源文件不动。主项目升级后看网关启动日志的自检行：
  `✅ 自检通过` = 映射仍有效；`⚠️` = 主项目改了这些行，需同步更新
  `gateway.js` 的 `REWRITES` 数组（对照 `grep -n "localhost:8080" js/`）。

## 一、无头后端打包与上传

> 本地不需要传整包（1.3GB+ 里 models/Real-ESRGAN/pi 等云端都用不上）。
> 在本地项目里打"无头后端"精简包（约十几 MB）：

```
双击 cloud\pack-server.bat（一键：打包 + 打开产物文件夹）
或命令行：node cloud/pack-server.js
```

包内 = 后端+前端本体（server.js / routes / utils / js / css / index.html /
help.html / image / workflows / manga-templates / lumen_nodes）+ `cloud/`
网关。**不含**：pi/（agent 模式选装，要用就从完整包单独拷 `pi/` 进服务器）、
models/、Real-ESRGAN/、runtime/、node_modules（服务器现装）、本地数据
（data/ save/ tag/ 服务器首次启动自动建全新目录）。

上传 zip 到 VPS（例如解压到 `D:\lumen-light\`），服务器上装好 Node.js 后：

**一键方式（推荐）**：双击根目录的 `服务器一键启动.bat` —— 首次运行自动
装好前后端依赖并拉起后端与网关两个服务窗口；之后每次启动也用它（已装
依赖时秒开）。窗口关闭 = 停止对应服务；长期常驻改用 NSSM（见下两节）。

**手动方式**（等效，习惯命令行用这个）：

```
cd D:\lumen-light
npm install --omit=dev           # 只装生产依赖（express/sharp/ws/archiver/puppeteer-core 等）
```

## 二、启动原始后端（8080）【手动等效，一键启动可跳过】

1. 命令行 `node server.js` 试跑，确认控制台出现
   `LumenLight 后端: http://localhost:8080`
   （不要用本地机的 start-server.bat——它不在本包内，且其 8080 端口
   占用清理会杀掉一键启动拉起的后端）
2. 常驻：用 NSSM 注册成系统服务（比计划任务稳）：
   ```
   nssm install LumenLight "<Node.js 安装路径>\node.exe" "server.js"
   nssm set LumenLight AppDirectory D:\lumen-light
   nssm start LumenLight
   ```
   （Node 路径用 `where node` 查；不用 --watch 热重载：热重载会连带杀掉
   pi 子进程、中断长任务）

## 三、启动网关（8081）【手动等效，一键启动可跳过】

```
cd D:\lumen-light\cloud
npm install
node gateway.js
```
- 首次启动自动生成 `cloud/config.json`，里面的 `token` 就是访问码
  （也可改成自己的值后重启网关；环境变量 `LUMEN_GATEWAY_TOKEN` 优先级更高）
- 启动 1.5 秒后日志出现自检行，确认 `✅ 自检通过：出站地址改写映射有效`
- 常驻：`nssm install LumenGate "<Node.js 路径>\node.exe" "gateway.js"`
  （AppDirectory 设为 `D:\lumen-light\cloud`）

## 四、域名 HTTPS（Caddy）

1. DNS：把域名 A 记录指向 VPS 公网 IP
2. 下载 caddy Windows 版（caddy.exe），和 `cloud/Caddyfile` 同目录放好
3. 把 Caddyfile 里的 `your.domain.com` 改成你的域名
4. 验证并试跑：`caddy validate --config Caddyfile` → `caddy run --config Caddyfile`
5. 注册服务常驻（管理员 CMD）：
   ```
   sc create LumenCaddy binPath= "D:\caddy\caddy.exe run --config D:\caddy\Caddyfile" start= auto
   ```
6. Caddy 首次启动自动申请 Let's Encrypt 证书并自动续期

## 五、防火墙与安全组（两层都要配）

| 端口 | 云控制台安全组 | Windows 防火墙 | 用途 |
|---|---|---|---|
| 443/TCP | ✅ 开 | ✅ 开 | 域名 HTTPS 门 |
| 8081/TCP | ✅ 开 | ✅ 开 | IP 直连门（网关） |
| 80/TCP | 可选 | 可选 | Caddy http→https 跳转 |
| **8080/TCP** | ❌ **不开** | ❌ 不开 | 内层后端，只许本机访问 |
| 3389/TCP | ⚠️ 开但收紧 | — | RDP：安全组限源 IP / 改端口 / 强密码 |

Windows 防火墙命令（管理员）：
```
netsh advfirewall firewall add rule name="LumenGate-8081" dir=in action=allow protocol=TCP localport=8081
netsh advfirewall firewall add rule name="LumenCaddy-443"  dir=in action=allow protocol=TCP localport=443
```
（8080 不加规则 = 默认拦，保持现状即可；如已有放行规则务必删除）

## 六、网页桥接（海外 AI 站点）

1. VPS 装 Chrome（或用预装 Edge），RDP 远程桌面里确认能打开
2. 应用里：设置 → 网页桥接 → 浏览器路径指到 chrome.exe/msedge.exe
3. **首次登录**：网关 headless 关闭（默认就是有头），RDP 里能看到浏览器窗口，
   直接登录目标站点一次；登录态存 `data/webbridge/profile/`，长期有效
4. 站点适配器现状：目前只有豆包——Gemini/ChatGPT 等新站点需要后续逐站
   写适配器（`utils/webbridge/adapters/` 一站一文件，独立功能开发）

## 七、日常使用

- 浏览器打开 `https://你的域名`（或 `http://VPS_IP:8081`）→ 输访问码 → 进画布
- 登出：浏览器访问 `/__auth/logout`
- API/桥接的产物、存档、资产全在 VPS 磁盘：定期备份
  （应用内 文件菜单 → 备份导出 zip 拉回本地；或直接压缩 `data/` 与 `save/`）
- **单用户语义**：同一存档不要两个客户端同时编辑（后写覆盖前写）

## 八、排错速查

| 现象 | 排查 |
|---|---|
| 打不开登录页 | 安全组/防火墙 8081 未放行；gateway 未启动（NSSM 看服务状态） |
| 登录后一直「后端未启动」 | 原始后端没跑（8080）；`netstat -ano | findstr :8080` 确认 |
| 页面能开但实时保存/回流失效 | F12 Console 看 WebSocket 连的是不是当前域名/IP（应是），连接失败查 443/8081 链路 |
| 网关日志出现 ⚠️ 自检 | 主项目升级改了那 9 处 → 更新 gateway.js 的 REWRITES 映射 |
| Caddy 拿不到证书 | DNS 未生效 / 443 未放行 / 域名被国内解析拦截（海外 VPS 用海外 DNS 解析验证） |

## 九、升级流程（精简部署专用）

1. 本地：拉取最新项目代码 → `node cloud/pack-server.js` 重新打包
2. 上传 zip → 服务器解压覆盖代码文件（**保留**服务器的 `data/`、`save/`、
   `tag/` 与 `cloud/config.json`——解压前把这几项挪出去或确认解压工具
   不删除既有目录）
3. 依赖有变化时重跑 `npm install --omit=dev`
4. 重启两个服务（NSSM restart LumenLight / LumenGate）
5. 看网关启动日志自检行确认改写映射仍有效
6. 注意：精简包不含 `update.bat`（应用自更新会拉完整发行包覆盖，
   与精简部署冲突）——升级一律走本流程重新打包
