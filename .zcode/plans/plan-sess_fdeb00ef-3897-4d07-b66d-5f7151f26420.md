# 画布撤销/重做（Ctrl+Z / Ctrl+Shift+Z）实施计划

## 范围

**覆盖**（结构类操作）：对象/节点/组的拖动移动、缩放调整、删除（含 Delete 键与剪切）、新增（右键建节点/上传/拖放/粘贴/生成落图/桥接落图）、连线建立与断开（含生图节点连线的"替换旧入边"语义）、编组创建/解组/改名/配色/组拖动/组缩放。

**不覆盖**：节点内部编辑（提示词文本、Comfy 参数等——聚焦时有浏览器原生撤销）、生成行为本身、ImageStudio（已有独立历史栈）、z-order 变化（现有实现里 z 序是选择的副作用）、面板提示词区。

## 核心设计：命令栈（非快照）

画布图片是重对象，全量快照会撑爆内存；且探索确认 destroy() 后的节点不可复活，但删除的**位图对象可以保留原对象引用**（Image 元素仍在内存），恢复时按原数组下标 splice 回去——id 不变、连线无需重映射。只有**节点**删除需要走重建路径：存 `toJSON()` 快照，恢复时按 ProjectSerializer.restoreNodes 的 type 分发新建（新 id + 连线经 idMap 重映射，既有模式）。

### 新文件 `js/canvas/CanvasHistory.js`

```
API: push(cmd) / undo() / redo() / canUndo / canRedo / clear()
cmd = { label, undo(), redo(), onEvict?() }
```
- 栈上限 100，新 push 截断 redo 尾部（同 StudioHistory 模式）
- `undo()/redo()` 期间置 `_applying` 标志：各记录点检查它避免撤销动作本身被记成新命令
- 每次 undo/redo 结束调 `canvas.draw()`（ChangeWatcher 挂在 draw 上，autosave 自动标脏，无需额外接线）
- **延迟视频清理**：删除视频对象时原本立刻调后端 DELETE /api/videos（ImageManager.js:232）。改为删除时若可撤销则跳过后端清理，把清理任务挂到命令上；命令被截断/淘汰/清栈时才真正执行。否则"删除→撤销"后文件已没、视频变死链

### 命令覆盖与接入点

| 操作 | 记录点 | 命令内容 |
|---|---|---|
| 拖动移动 | CanvasInteraction `_startDrag`:364 快照起点 + onMouseUp:745 提交（对比有无位移） | `{id: from{x,y} → to{x,y}}`（批量成员） |
| 缩放调整 | `_startResize`:268 + onMouseUp 提交 | from/to 矩形 |
| 组拖动/组缩放 | `_startGroupDrag`:292 / `_startGroupResize`:318 + onMouseUp | 组+成员位置批量快照 |
| 删除 | CanvasInteraction.onKeyDown:201-220 的删除循环改为整体调 `history.recordDelete()`；cut (CanvasClipboard:294) 同 | 对象引用（位图/视频）或 toJSON（节点）+ 原数组下标 + 相连连线清单 + 被删组记录 |
| 新增 | CanvasContextMenu:260-354、ImageManager.add:28 / addImage:80、PlaceholderManager.replace、CanvasClipboard.pasteInternal | 对象快照（undo=移除，redo=重建/放回） |
| 连线 | CanvasConnections.add:159 / remove:196 内部记录（单收口）；add 的替换语义快照被挤掉的旧边 | 边记录 `{fromId,toId,order}` |
| 编组 | GroupManager.add:95 / delete:120 / setColor:139 / rename:437 | 组记录 / title、color 前后值 |

删除恢复顺序：先对象（按原下标从大到小 splice 回去）再连线；与 ProjectSerializer 的"对象→组→连线"次序一致。

### 键盘与 UI

- `CanvasInteraction.onKeyDown`（CanvasInteraction.js:154）的 Ctrl 组合块内加：Ctrl+Z → undo、Ctrl+Shift+Z / Ctrl+Y → redo。现有守卫自动生效（焦点在输入框/编辑器打开时不触发，文本框内保留原生撤销）
- 新增 `canvasHistoryChanged` 事件（沿用 CustomEvent 惯例）+ 左下角轻量 toast（"已撤销：移动图片"，复用现有浮层样式），提升可发现性

### 边界处理

- 存档打开/恢复/新建画布 → `history.clear()`（挂到 ProjectSerializer.restoreProject 尾部 + NewCanvasManager），清栈时 flush 待清理视频
- `_applying` 防重入；restoreProject 全量恢复走已有 `_isRestoring` 抑制，不经过命令栈

### 测试

- 新增 `test/canvas/canvasHistory.test.js`：栈纪律（截断 redo、上限淘汰、onEvict 触发）用注入的假命令单测，不依赖 DOM（核心逻辑与 DOM 解耦）
- 手工验证清单：删图→撤回、删视频→撤回→视频仍可播、删节点带连线→撤回→连线恢复、连线替换→撤回恢复旧边、拖动→撤回归位、存档切换后栈清空

### 实施顺序

1. CanvasHistory 模块 + 单测（纯栈逻辑）
2. 接入键盘 + Canvas 初始化 + 清栈点
3. 删除/新增/连线/编组记录点
4. 手势提交（移动/缩放/组操作）
5. 视频 deferred cleanup + 手工全量回归

不改动后端；前端三个文件改动集中，index.html 加一个 script 标签。
